# Private CSV import implementation plan

> Execute inline unless Milind explicitly requests delegated agents. Do not commit, push, publish, deploy, or modify production data without separate explicit approval. Use red/green TDD for each production change.

**Goal:** Accept private CSV files up to 20 MiB and 2,000 data rows, persist each import once, show per-import progress, and classify gradually without a paid worker.

**Architecture:** The browser uploads directly to a private Vercel Blob store using an authenticated token endpoint. Neon owns import state and deduplicated FeedbackItems. The serverless classifier from `2026-09-23-serverless-classification.md` processes ID-only messages; a daily cron repairs abandoned imports and missed work.

**Tech stack:** Next.js 16/React 19, Prisma 5/PostgreSQL (Neon), `@vercel/blob` >= 2.3, PapaParse, existing Zod/Jest/Playwright setup.

**Spec:** `docs/superpowers/specs/2026-09-23-no-worker-csv-import-design.md` (approved with corrected scheduling 2026-09-23). **Dependency:** Complete and preview-verify `docs/superpowers/plans/2026-09-23-serverless-classification.md` first. The 20 MiB limit stays inactive until this direct Blob path passes preview.

## Global constraints

- Private Blob only. Browser never receives Blob read/write credentials. Authenticate and bind upload to server-created organization/import ID.
- Reject files above 20 MiB and above 2,000 data rows explicitly. No partial import on over-limit files; never silently slice rows.
- Database partial unique index enforces one live import (`UPLOADING`, `IMPORTING`, `PROCESSING`) per organization.
- Eliminate `CsvImportPayload`, `getCsvQueue`, `CSV_IMPORT`, and CSV worker handler; no legacy full-row queue path remains.
- Queue payloads contain IDs only. Manual/reclassification work takes priority; CSV can take days at free Groq limits.
- Never log CSV content, private Blob URL, secrets, or complete environment values.
- Do not push the taxonomy migration or apply production migrations under this plan.
